# 6. Testing

> **Audience.** Anyone running, debugging, or extending the test suite.

The toolkit has **five independent test layers** stacked to give different
confidence guarantees. Read this doc top-to-bottom to understand what each
layer proves and how to run / extend it.

> **v2 review-fixes update.**
> - Solidity unit test count is now **43** (was 33). Added coverage for
>   Ownable rotation, customVerifier allowlist, quorum, dynamic bindings,
>   job-binding mismatch, etc.
> - Solidity integration test count is **15** (was 16). The SDK
>   cross-validation test was removed — its fixture pinned a hookAddress
>   that no longer matches a fresh deployment under the new binding
>   model. The SDK's own 42 unit tests cover the ABI shape it generates;
>   re-adding a Solidity-side cross-validation will require deterministic
>   deployment via `vm.etch` + storage cheatcodes.
> - SDK test count is **42** (was 35). Added: `computeJobBinding`
>   variance, `buildSpec(job, ctx)` per-step binding population,
>   dynamic-binding (`fromExtractKey`) encoding, `additionParams`-with-
>   binding canonical form.

## 6.1 The six layers

```
┌────────────────────────────────────────────────────────────────────────────┐
│ Layer 6: On-chain E2E         Real Base Sepolia, real Primus signed         │
│ (manual / scripted)           attestations, real wallets. The strongest     │
│                               possible confidence — also the slowest        │
│                               (~30-60s per scenario, costs testnet ETH).    │
├────────────────────────────────────────────────────────────────────────────┤
│ Layer 5: Fork tests (real     Forge fork of Base Sepolia. Uses the LIVE     │
│ attestation)                  Primus contract. Reads a real signed          │
│                               attestation fixture (pre-generated by Layer   │
│                               6) and feeds it through hook→Primus.          │
├────────────────────────────────────────────────────────────────────────────┤
│ Layer 4: Fork tests (ABI      Forge fork of Base Sepolia. Sends             │
│ compatibility)                deliberately-broken attestations to the LIVE  │
│                               Primus verifier, asserts the right internal   │
│                               check fires. Proves our struct ABI matches.   │
├────────────────────────────────────────────────────────────────────────────┤
│ Layer 3: Integration tests    Local forge VM. Real UUPS-proxied ERC-8183 +  │
│                               real hook + real extension verifier +         │
│                               SDK-generated bytes round-tripped through.    │
├────────────────────────────────────────────────────────────────────────────┤
│ Layer 2: SDK unit tests       vitest. Pure-function tests of placeholder    │
│                               substitution, spec building, ABI encoding,    │
│                               and runJob orchestration against a mock       │
│                               attestor. No network, no contracts.           │
├────────────────────────────────────────────────────────────────────────────┤
│ Layer 1: Hook unit tests      forge with mocked core + mocked verifier.     │
│                               Exhaustive happy/revert paths in isolation.   │
└────────────────────────────────────────────────────────────────────────────┘
```

Each layer guards against a different class of bug. Removing any layer
opens a category of regressions that the others cannot catch.

## 6.2 Layer 1 — Hook unit tests (33 tests)

**Location:** `test/unit/ZkTlsAttestationHook.t.sol`
**Run:** `forge test --match-path 'test/unit/*'`

What this layer proves: the hook's `_postFund` and `_preSubmit` logic
behaves correctly against every documented spec configuration, attestation
shape, and failure mode — in isolation, with the core and the verifier
mocked.

Tests cover:

| Category | Examples |
|---|---|
| Constructor | rejects zero core / zero verifier |
| Spec config (in `_postFund`) | rejects empty steps, too many steps, invalid binding direction, invalid binding location, missing deliverable source step, double-configure |
| Happy paths | single step, two steps with binding, pinnedAttestor match, extensionVerifier accepted |
| Single-step revert paths | method/url/body/responseResolve/additionParams hash mismatch, stale, pinnedAttestor mismatch, verifier rejects, deliverable mismatch, step count mismatch |
| Multi-step revert paths | binding missing from source, binding missing from destination |
| Extension layer | customVerifier accepted, customVerifier rejects |
| Replay | spec already configured, already validated |
| Access | onlyERC8183 (caller not the core) |
| Metadata | requiredSelectors returns fund + submit, supportsInterface for IERC8183Hook + IERC8183HookMetadata + IERC165 |

These tests run in milliseconds. They are the first thing CI should run on
any hook change.

### How the mocks work

`MockCore` is a stand-in that:
- exposes a `setJob(jobId, hookAddr)` method so tests can pretend a job
  exists with a particular hook.
- exposes `callBefore` / `callAfter` so tests can invoke the hook's
  callbacks AS IF the call came from the core.

`MockZkTlsVerifier` is a one-toggle accept/reject verifier. By default it
silently approves anything; flipping `setRevert(true)` makes it
unconditionally revert.

## 6.3 Layer 2 — SDK unit tests (35 tests)

**Location:** `sdk/test/*.test.ts`
**Run:** `cd sdk && pnpm test`

Coverage by file:

| File | What it tests |
|---|---|
| `placeholder.test.ts` (11) | `applySubstitutions` correctness across url/header/body locations, JSON-aware escape for body, percent-encode for url, multiple substitutions, missing-key error, etc. |
| `specBuilder.test.ts` (13) | `buildSpec` produces the right struct, `hashResponseResolves` ignores order vs. content, placeholder resolution before hashing, all the spec validation errors |
| `encoding.test.ts` (5) | `encodeFundOptParams` / `encodeSubmitOptParams` round-trip cleanly through `decodeAbiParameters`, `computeDeliverable` matches `keccak256(toBytes(data))` |
| `runJob.test.ts` (6) | Multi-step orchestration with an injected mock attestor, placeholder substitution at runtime, defensive guards (attestor cannot return a different URL), error propagation |

Notable: tests inject a synthetic `AttestorFn` rather than calling Primus.
This makes the suite hermetic (no Primus credentials needed in CI) but
keeps `runJob`'s orchestration logic fully exercised.

## 6.4 Layer 3 — Solidity integration tests (16 tests)

**Location:** `test/integration/`
**Run:** `forge test --match-path 'test/integration/*'`

Three test files, three different stacks:

### `FullLifecycle.t.sol` (3 tests)

Spins up the **real** `ERC8183` (UUPS-proxied, initialised) + real
`MockUSDC` + real hook + an always-accept mock verifier. Drives the full
`createJob → setBudget → fund(spec) → submit(atts) → complete` lifecycle
and asserts:

- The escrowed budget reaches the provider on a happy path.
- A tampered attestation aborts at submit, leaving the escrow intact —
  the client can then `reject` and recover the funds.
- `claimRefund` works after expiry even with a hook attached
  (`claimRefund` is intentionally not hookable).

### `PriceDeviationVerifier.t.sol` (4 tests)

Same stack, plus the `PriceDeviationVerifier` example extension. Tests
the customVerifier code path: accept when prices are within tolerance,
reject when they deviate, reject when the key is missing, reject bad
constructor config.

### `LLMAnswerLengthVerifier.t.sol` (8 tests)

Tests our reference `LLMAnswerLengthVerifier` (the one deployed on Base
Sepolia). Covers constructor validation, happy path (length in band),
rejection (too short / too long / missing key / unterminated string),
and the escaped-quote edge case.

### `SdkCrossValidation.t.sol` (1 test)

The most subtle and most important integration test. Reads bytes
generated **by the TypeScript SDK** from
`test/fixtures/sdk-fund.hex`, `sdk-submit.hex`, `sdk-deliverable.hex`,
feeds them through the **actual** hook contract, and asserts validation
succeeds. If the SDK's hashing or ABI-encoding ever drifts from the
Solidity hook's expectations, this test fails.

To regenerate the fixture after changing the SDK or hook:

```bash
cd sdk && pnpm tsx scripts/dump-fixture.ts
forge test --match-path 'test/integration/SdkCrossValidation*'
```

## 6.5 Layer 4 — ABI compatibility fork tests (5 tests)

**Location:** `test/fork/PrimusVerifierFork.t.sol`
**Run (with RPC):** `BASE_SEPOLIA_RPC_URL=https://sepolia.base.org forge test --match-path 'test/fork/PrimusVerifierFork*'`

Opt-in tests that fork Base Sepolia and call the **live** Primus
PrimusZKTLS at `0xCE7c…0afdE`. The tests use **deliberately broken**
attestations (empty signature array, 64-byte signatures, all-zero
signatures) — Primus will revert in each case, but **for the right
reason**: the signature length check, signer recovery, etc.

The point: each test verifies that our local `Attestation` struct is
ABI-compatible with the on-chain verifier. If the field shape ever drifts,
the verifier wouldn't even decode the calldata, and the revert reason
would change. Catching that drift is the value here.

Auto-skipping: when `BASE_SEPOLIA_RPC_URL` is not set, every test in this
file marks itself skipped (via `vm.skip`). `forge test` with no env
variables runs cleanly without these.

## 6.6 Layer 5 — Real-attestation fork test (1 test)

**Location:** `test/fork/RealAttestationE2E.t.sol`
**Run (with RPC + fixture):** `BASE_SEPOLIA_RPC_URL=https://sepolia.base.org forge test --match-path 'test/fork/RealAttestation*'`

This test consumes a **real signed attestation** produced by Primus, fed
through the **real on-chain verifier**, in a **forked** Base Sepolia EVM.

To produce the fixture (only once per fresh stack; needs Primus
credentials):

```bash
cd sdk
PRIMUS_APP_ID=0x... PRIMUS_APP_SECRET=0x... \
  pnpm tsx scripts/generate-real-fixture.ts
```

This emits `test/fixtures/real-fund.hex`, `real-submit.hex`,
`real-deliverable.hex` (gitignored — see `.gitignore`'s
`real-*.hex|.json` rules).

The test then:
1. Forks Base Sepolia.
2. Deploys a fresh hook against the **real** Primus verifier.
3. Reads the fixture and submits.
4. Asserts `hook.isValidated(jobId) == true`.

If this test passes, the entire on-chain path is sound: Primus's
signature is valid, the verifier accepts it, the hook accepts the
verifier's verdict.

This is where we caught the **millisecond timestamp bug** in the
unified-layer staleness check. See
[08-troubleshooting](08-troubleshooting.md) §"Timestamp units".

## 6.7 Layer 6 — On-chain E2E (manual / scripted)

**Location:** `sdk/scripts/onchain-*.ts`
**Run:** with the right env vars (see [05-deployment](05-deployment.md))

These are not "tests" in the forge sense — they make real on-chain
transactions on Base Sepolia. They prove the deploy script works, the
real wallets can drive the lifecycle, gas estimates are sane,
BaseScan can index the events, etc.

Available scenarios:

| Script | What it does |
|---|---|
| `onchain-e2e.ts` | Single-step CoinGecko BTC/USD lifecycle |
| `onchain-multistep.ts` | Two-step CoinGecko USD → EUR with a static binding |
| `onchain-llm.ts` | CoinGecko → LLM (OpenAI-compatible) with body binding |
| `onchain-llm-with-verifier.ts` | Same as LLM but with `customVerifier` (loose by default; pass `VERIFIER_ADDR=` for the tight one to demo rejection) |

Each script accepts `JOB_ID=<n>` to reuse an existing Open job (skipping
the `createJob` tx).

The shared lifecycle implementation is in `sdk/scripts/lib/lifecycle.ts`
— it's worth reading once if you want to write your own scenario.

### Real-attestation generation as a side effect

Running any of the on-chain scripts produces real signed attestations.
You can stash them as test fixtures using the dump scripts:

```bash
# Synthetic (no Primus credentials needed)
pnpm tsx scripts/dump-fixture.ts          # sdk-*.hex

# Real Primus
PRIMUS_APP_ID=... PRIMUS_APP_SECRET=... pnpm tsx scripts/generate-real-fixture.ts
```

## 6.9 Adding a new test

### Adding a hook unit test

Edit `test/unit/ZkTlsAttestationHook.t.sol`. The existing tests are good
templates — pick the closest one and adapt. Always:

- Use the `MockCore` setup from `setUp()`.
- Build the spec with `_bareSpec(steps, bindings)` helper.
- Use `_fund(...)` and `_submit(...)` helpers to invoke the hook.
- For revert tests use `vm.expectRevert(ZkTlsAttestationHook.YourError.selector)`.

### Adding a SDK unit test

Drop a `.test.ts` file into `sdk/test/`. vitest picks it up automatically.
The pattern for orchestration tests is in `sdk/test/runJob.test.ts` (uses
an injected mock attestor).

### Adding an integration test

If you need a real ERC-8183 or a real extension verifier, copy the setup
from `FullLifecycle.t.sol` or `LLMAnswerLengthVerifier.t.sol`. Use the
mock zkTLS verifier (`AcceptingVerifier`) unless you specifically need
real signature checks.

### Adding a fork test

Add a `test/fork/*.t.sol` file. Pattern:

```solidity
contract MyForkTest is Test {
    bool internal forked;
    function setUp() public {
        string memory rpc = vm.envOr("BASE_SEPOLIA_RPC_URL", string(""));
        if (bytes(rpc).length == 0) return;
        vm.createSelectFork(rpc);
        forked = true;
    }
    function test_Something() public {
        vm.skip(!forked);
        // ... actual test
    }
}
```

`vm.skip` is essential — it lets `forge test` pass in CI without RPC
access.

### Adding an on-chain E2E scenario

Define your `JobDefinition`, then call `runScenario` from
`sdk/scripts/lib/lifecycle.ts`. See `sdk/scripts/onchain-multistep.ts` for
a minimal template (~40 lines including comments).

## 6.10 Bytecode equivalence check

A useful sanity check after redeploy: verify the deployed bytecode matches
your local artifact (modulo the constructor immutables and the Solidity
metadata trailer):

```bash
source $HOME/.zshenv

ONCHAIN=$(cast code 0xd954517B4C4f0D3A9be69F4d4e2Cbc6f30ed9D1A \
  --rpc-url https://sepolia.base.org)

LOCAL=$(python3 -c "import json; \
  print(json.load(open('out/ZkTlsAttestationHook.sol/ZkTlsAttestationHook.json'))['deployedBytecode']['object'])")

python3 -c "
on='$ONCHAIN'.lower(); lo='$LOCAL'.lower()
core='2cf22d4013f7228090c6a77b134114ad0761c138'   # ERC8183 core
primus='ce7cefb3b5a7eb44b59f60327a53c9ce53b0afde'  # Primus verifier
zeros='0'*40
print('core matches  :', on.count(core)   == lo.count(zeros) - 2)
print('primus matches:', on.count(primus) == 2)
print('% bytes match  :', sum(1 for i in range(min(len(on),len(lo))) if on[i]==lo[i]) * 100 // len(on))
"
```

For our hook the answer is "98.85% bytes identical; 5 occurrences of the
ERC8183 address + 2 of the Primus address account for the rest" — the 7
immutable slots in the artifact's bytecode each got replaced with the
real address at deploy time.
